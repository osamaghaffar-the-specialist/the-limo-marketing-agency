# TLMA Authority & Proof Sprint — 2026-10-13

The current technical/on-page foundation is already strong enough that more keyword stuffing is unlikely to be the highest-impact next move. Current Search Console data shows Google is testing TLMA on the correct commercial themes, but rankings remain mostly deep because the site is still young, only 7/21 tracked URLs are indexed, branded demand is zero, and authority/proof is weaker than established niche competitors.

## Current TLMA proof strengths
The existing `case-studies-results.html` page already has several good trust principles:
- it explicitly says not to invent ROAS, revenue or booking-growth percentages when exact KPIs are unavailable;
- it separates public reputation/review context from causation;
- it names four client stories;
- it links to current public client websites where applicable;
- it explains starting point, work delivered and the customer journey rather than forcing every case into one template.

These are directionally strong and should be preserved.

## Critical proof guardrail
The page currently names four case studies in visible content/schema:
- NYC United Limo
- King & Queen Limo
- NYC Executive Limo
- NYC Lux Ride

Before we amplify these stories on the homepage, SEO page, Google Ads page, external profiles or future authority assets, each named relationship must have an evidence record. No assumption that a public website link automatically equals permission to use the brand as a client case study.

## Evidence ledger required for each named case study
For every client/story, record:
1. client/company name
2. contact/relationship evidence
3. exact work TLMA/Usama performed
4. dates/timeframe if known
5. permission to use company name/logo/story publicly
6. public URLs/screenshots that can be shown
7. exact KPI sources, if any
8. metrics that are safe to publish
9. metrics that must NOT be published
10. approved wording for attribution

If permission or evidence is missing, do not delete the work history blindly; instead label the story conservatively or hold amplification until verified.

## Competitor proof standard observed in current SERPs
Established limo marketing competitors commonly surface combinations of:
- number of operators/websites served
- years exclusively in ground transportation
- named client stories and interviews
- live portfolio links
- lead counts or ranking lifts tied to a specific case
- testimonials
- founder identity / specialization
- industry-specific education and original content
- transparent frameworks and deliverables

TLMA should not copy unverifiable numbers or aggressive guarantees. The correct response is to build stronger first-party evidence.

## Proof stack TLMA should build

### Layer 1 — Verifiable work artifacts
- live websites built or materially improved
- booking-system demos/screenshots
- admin portal screenshots
- anonymized campaign screenshots where appropriate
- technical audits / before-after implementation notes

### Layer 2 — Permission-based case studies
Structure each as:
Problem -> Evidence of starting point -> Work delivered -> What changed -> Verified outcome -> What is not being claimed -> Client approval.

### Layer 3 — Original operating data
When enough clean data exists, publish anonymized niche benchmarks such as:
- limo Google Ads CPL / booking CPA ranges
- form-start to completed-booking conversion
- mobile vs desktop lead behavior
- search terms by ride intent
- booking-form drop-off patterns

Do not publish a benchmark until sample size, date range and methodology are documented.

### Layer 4 — Linkable authority assets
Priority sequence:
1. UK Taxi Dispatch System Prices research (release gated)
2. Limo SEO Technical Audit Checklist — 90+ checks
3. Limo Google Ads benchmark / audit framework when enough real data exists

## What NOT to do now

## Immediate execution plan

### A. Indexing adoption
Continue monitoring the 13 already requested non-indexed URLs; request the remaining `terms.html` after quota reset. No repeat submissions.

### B. GA4 conversion correctness
Mark `generate_lead` as a Key Event in GA4. Keep it success-only; do not count raw button clicks as leads.

### C. Proof verification
Start with NYC Lux Ride because the current project history has the clearest implementation trail. Build a permission/evidence checklist before expanding the case study.

### D. Competitor-gap response
Do not try to beat mature competitors by making bigger unsupported claims. Beat them on:
- transparent methodology
- real artifacts
- clearer proof boundaries
- booking/marketing integration depth
- original research
- technical detail

### E. Homepage proof upgrade gate
Do not add new headline KPI cards to the homepage until at least one case study has verified public proof/permission. Once verified, homepage proof should link to the full story instead of presenting contextless numbers.
